# IMP-007: Establish Improvement Backlog Infrastructure Under 06-evolution/backlog/

## Status

Proposed

## Layer

Evolution

## Theme

Create the `06-evolution/backlog/` directory with the backlog overview template and a `candidates/` directory, ready to accept future improvement work.

## Evidence

- `docs/06-backlog/` (currently empty) — Will become `docs/06-evolution/` after IMP-001.
- `.opencode/templates/product-breakdown/layers/06-evolution.md` — Expected artifacts: roadmap.md, backlog.md, risks.md, changelog.md, decisions/.
- `.opencode/templates/product-breakdown/templates/improvement-backlog-overview-template.md` — Specifies backlog location: `product-breakdown/06-evolution/backlog/improvement-backlog.md`, with candidates in `candidates/` and completed items in `completed/`.
- `.opencode/agents/orchestrator-improvement.md` — The improvement agent expects `product-breakdown/06-evolution/backlog/` as the canonical backlog location.
- Current `docs/06-backlog/` is empty — no backlog, no risks, no changelog.

## Current Pain Or Risk

The improvement workflow (orchestrator-improvement agent) specifies `product-breakdown/06-evolution/backlog/` as the canonical backlog location, but no such directory structure exists. The `06-backlog/` directory is empty. Improvement candidates discovered by the improvement workflow have no home. Improvement work that is accepted cannot be tracked in a structured backlog.

## Proposed Improvement

After IMP-001 renames `06-backlog/` → `06-evolution/`, create the following structure under `docs/06-evolution/`:

- `docs/06-evolution/backlog/improvement-backlog.md` — The overview file, using the improvement-backlog-overview-template.md format.
- `docs/06-evolution/backlog/candidates/` — Directory for individual IMP-NNN.md files.
- `docs/06-evolution/backlog/completed/` — Directory for completed improvement implementations.

Populate `improvement-backlog.md` with the overview table for the candidates produced by the current improvement workflow (including the 7 candidates in this report). Each candidate gets an `IMP-NNN.md` file in `candidates/`.

Additionally, create starter files that the evolution layer expects:
- `docs/06-evolution/roadmap.md` — Document the planned evolution of the package (e.g., "stabilize docs structure," "add automated traceability checks").
- `docs/06-evolution/risks.md` — Document known risks (e.g., "docs/template synchronization may drift without automation").
- `docs/06-evolution/changelog.md` — Start a changelog capturing notable changes to the package.

## Expected Benefit

The improvement workflow has a canonical home for its output. Improvement candidates are persisted between workflow runs. The evolution layer matches the template's expected artifacts. The `product-breakdown/06-evolution/backlog/` path that the improvement agent references finally exists.

## Risk And Blast Radius

**Blast radius:** New files and directories only. No existing files moved or modified (except as part of IMP-001's directory rename). No agent behavior changes.

**Risk:** Low. The backlog structure is empty starter content. If the improvement workflow is never run, the backlog remains empty but does not harm anything.

**Mitigation:** The initial population of candidates should come from this improvement workflow output. Subsequent improvement runs add to the candidates/ directory.

## Suggested Priority

Low — Depends on IMP-001 (directory rename) for the correct `06-evolution/` name. The backlog content can be prepared in parallel and placed after the rename.

## Task Contract Seed

After IMP-001 completes, create `docs/06-evolution/backlog/improvement-backlog.md` using the improvement-backlog-overview-template.md format. Create `candidates/` and `completed/` subdirectories. Populate the overview with the entries from this improvement workflow. Create `IMP-001.md` through `IMP-007.md` files in `candidates/`. Then create `roadmap.md`, `risks.md`, and `changelog.md` with initial content extracted from this report.
