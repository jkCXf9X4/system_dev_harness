# IMP-004: Create Missing Operation Layer Directory

## Status

Proposed

## Layer

Evolution

## Theme

Create `docs/05-operation/` with starter artifacts documenting how the package is deployed, used, and maintained.

## Evidence

- `docs/` directory — No `05-operation/` directory exists.
- `.opencode/templates/product-breakdown/layers/05-operation.md` — Expected artifacts: runbook.md, monitoring.md, deployment-process.md, incident-response.md, support-model.md, decisions/.
- `docs/README.md` — Current note: operation is "package usage and copied-payload operation in `README.md`."
- `README.md` (root) — Contains copy instructions for target repos.
- `.opencode/agents/orchestrator.md` — Defines the workflow orchestration logic that is the "operation" of this package.
- No single document currently answers "how do I deploy, run, monitor, or support this package?"

## Current Pain Or Risk

Operation documentation is scattered. The root `README.md` covers copy/paste installation. The orchestrator agent prompt covers the workflow lifecycle. There is no runbook, no incident-response guidance, no support model, and no monitoring documentation. A maintainer troubleshooting a workflow failure must read multiple agent prompts and the root README to piece together operational knowledge. The package's own operation — how it runs as an OpenCode workspace — is undocumented.

## Proposed Improvement

Create `docs/05-operation/` with starter files:

- `docs/05-operation/deployment-process.md` — Document how the package is "deployed" (copied into a target repo via `opencode.json` and `.opencode/`), including versioning strategy and update process.
- `docs/05-operation/runbook.md` — Document common operational tasks: running the workflow, handling a blocked task, approving waivers, re-running a stage.
- `docs/05-operation/support-model.md` — Document who maintains this package, how issues are reported, and what support expectations exist.
- `docs/05-operation/monitoring.md` — Describe how workflow health is observed (e.g., reviewing final reports, checking for stale improvement candidates).
- `docs/05-operation/incident-response.md` — Document what to do when a workflow breaks: orphaned artifacts, stale references, agent misbehavior.
- `docs/05-operation/decisions/` — Empty decisions directory for future operational decisions.

Extract content from root `README.md` and orchestrator agent prompt. Update `docs/README.md` to list `05-operation/`.

## Expected Benefit

Operational knowledge moves from implicit (scattered across README and agent prompts) to explicit in a dedicated layer. A maintainer can answer "how do I run and support this package?" in one place. The package aligns with the seven-layer template.

## Risk And Blast Radius

**Blast radius:** New files only; no existing files moved or modified (except `docs/README.md` layer table). No agent behavior changes. Content is extracted from existing documentation.

**Risk:** Low. The starter content describes current behavior and does not create new policy.

## Suggested Priority

Medium — No hard dependency on IMP-001 (though the directory will be named `05-operation/` after rename). Can be created in parallel with IMP-003.

## Task Contract Seed

Read the root `README.md` and the orchestrator agent prompt in `.opencode/agents/orchestrator.md`, extract operational knowledge (installation, workflow lifecycle, common failure modes), and write starter `deployment-process.md` and `runbook.md` files into `docs/05-operation/`. Create an empty `decisions/` directory. Update `docs/README.md`.

## Out Of Scope

- Creating the verification layer (handled by IMP-003).
- Changing the root `README.md` content beyond updating any path references.
- Adding decisions about operation (no OD decisions exist yet).
- Changing the `.opencode/agents/orchestrator.md` prompt.

## Notes

For this package, "operation" means package maintenance and target-repo deployment, not production server operation. The operation layer content will be lighter than a typical SaaS product's operation docs. The `incident-response.md` should cover workflow failures (orphaned artifacts, stale references) rather than server outages.
