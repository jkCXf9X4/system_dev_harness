# IMP-002: Distribute Technical Decisions Into Per-Layer Decisions/ Directories With Prefixed IDs

## Status

Proposed

## Layer

Evolution

## Theme

Move the five flat `docs/04-technical-decisions/` ADR files into per-layer `decisions/` subdirectories, renumber them with template-compliant prefix IDs, and add a root `decision-log.md` index.

## Evidence

- `docs/04-technical-decisions/0001-use-opencode-agent-workflow-for-orchestration.md` through `docs/04-technical-decisions/0005-copy-product-breakdown-guidance-into-agent-payload.md` — All five ADRs currently live in a flat, standalone directory.
- `.opencode/templates/product-breakdown/decision-placement.md` — Rule: "Place the decision in the layer where its consequences are most directly felt. The root decision-log.md is only an index."
- `.opencode/templates/product-breakdown/naming.md` — Expected prefixes: AD (architecture decision), IMD (implementation decision), TD (technology decision), etc.
- `.opencode/templates/product-breakdown/README.md` — Expected tree shows each layer may contain a local `decisions/` directory.
- `docs/05-implementation/implementation.md` — Cross-reference: "Implements ADR-0001 through ADR-0005."
- `docs/README.md` — Lists `docs/04-technical-decisions/*.md` as a dedicated layer.
- The template does not have a `04-technical-decisions/` layer; `04-verification/` occupies that slot.

## Current Pain Or Risk

The flat `04-technical-decisions/` directory violates the template's decision-placement rule. Decisions about architecture (ADR-0001, ADR-0003) sit alongside decisions about implementation payload location (ADR-0005). A reader must open each file to determine which layer it affects. There is no global decision log, so it is impossible to quickly answer "what decisions exist and where are they?" The sequential `0001-0005` numbering does not use the template's prefix scheme (`AD-*`, `IMD-*`, `TD-*`) and does not signal which layer owns each decision.

## Proposed Improvement

For each ADR file, determine the correct target layer per the decision-placement rules, rewrite it with a template-compliant ID and filename, move it into that layer's `decisions/` directory, and create a root `docs/decision-log.md` index.

Proposed mapping:

| Current file | Template ID | Target path |
| --- | --- | --- |
| `0001-use-opencode-agent-workflow-for-orchestration.md` | AD-001 | `docs/02-architecture/decisions/AD-001-use-opencode-agent-workflow-for-orchestration.md` |
| `0002-use-versioned-markdown-for-traceable-context.md` | AD-002 | `docs/02-architecture/decisions/AD-002-use-versioned-markdown-for-traceable-context.md` |
| `0003-use-external-agent-handoff-before-built-in-code-editing.md` | AD-003 | `docs/02-architecture/decisions/AD-003-use-structured-handoff-before-code-editing.md` |
| `0004-use-versioned-markdown-for-mistake-memory.md` | IMD-001 | `docs/03-implementation/decisions/IMD-001-use-versioned-markdown-for-mistake-memory.md` |
| `0005-copy-product-breakdown-guidance-into-agent-payload.md` | IMD-002 | `docs/03-implementation/decisions/IMD-002-copy-product-breakdown-guidance-into-agent-payload.md` |

Each moved file gets:
- An updated `# <ID>: <Title>` header (e.g., `# AD-001: Use OpenCode Agent Workflow For Orchestration`)
- A `## Layer` section (matching the template's decision-template.md format)
- Updated `## Traceability` section

The root `docs/decision-log.md` gets a table entry per decision with ID, Title, Layer, Status, Location, and Related artifacts.

Remove the old `docs/04-technical-decisions/` directory after all moves.

Update `docs/05-implementation/implementation.md` from "Implements ADR-0001 through ADR-0005" to list the new IDs explicitly. Update `docs/README.md` to remove the `04-technical-decisions/` row.

## Expected Benefit

Decisions live beside the artifacts they constrain, making the layered structure self-evident. The prefix IDs (AD, IMD, TD) immediately signal the owning layer. The root decision-log.md provides a global view without duplicating decision content. The old flat directory and generic ADR numbering are eliminated. The package docs become an example of the structure they prescribe.

## Risk And Blast Radius

**Blast radius:** 5 files moved, 5+ cross-references in `docs/README.md`, `docs/05-implementation/implementation.md`, and potentially other files. The old `docs/04-technical-decisions/` directory is deleted. Git history is preserved via `git mv`.

**Risk:**
- If a decision affects multiple layers, the placement rule says "highest layer where introduced." The mapping above places all orchestration/workflow decisions in architecture and the two payload-location decisions in implementation. This judgment should be reviewed.
- If the template's decision-template.md requires fields the current ADRs don't have (Alternatives Considered, Review Trigger), those must be added.

**Mitigation:** After move, run `git grep "ADR-000\d"` to confirm zero stale references. Review each moved file's header format against `decision-template.md`.

## Suggested Priority

High — The `04-technical-decisions/` directory occupies the slot where `04-verification/` should be (see IMP-003). Until decisions are distributed, the verification layer cannot be created at template position `04-`.

## Task Contract Seed

For each of the five ADR files in `docs/04-technical-decisions/`: (1) classify its owning layer per `decision-placement.md`, (2) `git mv` it into the target `decisions/` directory with the new filename, (3) rewrite its header to `# <PREFIX>-NNN: <Title>`, (4) add `## Layer` and update `## Traceability` sections, (5) add missing template fields (Alternatives Considered, Review Trigger). Then create `docs/decision-log.md` with the index table. Delete `docs/04-technical-decisions/`. Update all stale references.

## Out Of Scope

- Renaming the layer directories themselves (handled by IMP-001).
- Adding new decisions beyond the existing five.
- Creating verification or operation layer directories.
- Changing the `.opencode/templates/product-breakdown/` runtime payload.

## Traceability

- Intent: Vision.md traceability commitment
- Product: PC-006 (intent→decisions→implementation chain)
- Architecture: Architecture.md lists "Technical decisions" as a stable concept
- Implementation: Implementation.md lists "Implements ADR-0001 through ADR-0005"
- Verification: The old directory path is used nowhere in tests, but the moved files should be spot-checked

## Notes

The mapping in the Proposed Improvement section is a first-pass classification. The final layer assignment should be confirmed by the architecture review stage of the task contract. Specifically:
- ADR-0002 (versioned markdown for traceable context) could arguably be IMD (implementation decision about documentation format). Placed in Architecture because it describes the overall traceability strategy that architecture relies on.
- ADR-0004 (mistake memory) is about an implementation artifact (`.opencode/known-mistakes.md`) so IMD prefix is appropriate.
