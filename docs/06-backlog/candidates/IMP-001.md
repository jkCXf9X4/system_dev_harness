# IMP-001: Renumber And Rename Layer Directories To Match Template Numbering

## Status

Proposed

## Layer

Evolution

## Theme

Renumber the six docs layer directories to match the zero-indexed template numbering and rename them to use the canonical layer names.

## Evidence

- `.opencode/templates/product-breakdown/README.md` — Expected tree: `00-intent/`, `01-product/`, `02-architecture/`, `03-implementation/`, `04-verification/`, `05-operation/`, `06-evolution/`
- `docs/README.md` — Current mapping table explicitly maps template layers to differently-named and differently-numbered package docs directories.
- `docs/` directory listing — Current names: `01-intent/`, `02-product-commitments/`, `03-system-architecture/`, `04-technical-decisions/`, `05-implementation/`, `06-backlog/`
- 20+ cross-references across `docs/README.md`, `README.md`, `docs/01-intent/vision.md`, `docs/01-intent/use-cases.md`, and `tests/test_opencode_workflow_probes.py` reference the current paths.

## Current Pain Or Risk

The package tells target repos to use `00-intent/`, `01-product/`, `02-architecture/`, `03-implementation/`, `04-verification/`, `05-operation/`, `06-evolution/` but its own documentation uses a different scheme. This inconsistency creates confusion for anyone maintaining the package, makes auto-discovery by agents unreliable, and undermines the template's authority as the canonical structure. Over time, the docs tree diverges further from what the template prescribes.

## Proposed Improvement

Rename the six existing directories to align with the template:

| Current | Target |
| --- | --- |
| `docs/01-intent/` | `docs/00-intent/` |
| `docs/02-product-commitments/` | `docs/01-product/` |
| `docs/03-system-architecture/` | `docs/02-architecture/` |
| (flat `04-technical-decisions/` directory — handled by IMP-002) | n/a |
| `docs/05-implementation/` | `docs/03-implementation/` |
| (create `docs/04-verification/` — handled by IMP-003) | n/a |
| (create `docs/05-operation/` — handled by IMP-004) | n/a |
| `docs/06-backlog/` | `docs/06-evolution/` |

Use `git mv` for each rename to preserve history. Update all 20+ cross-references in the files identified in Evidence. Update `docs/README.md` to remove the mapping table (since directories will now match the template directly). Update root `README.md` to use new paths.

## Expected Benefit

The package docs tree becomes self-consistent with the template it prescribes. Directory names match the template's layer names and numbering. Agents discovering the docs tree can navigate it using the same rules they would apply to a target repo's `product-breakdown/` tree. The mapping table in `docs/README.md` becomes unnecessary, reducing ongoing maintenance.

## Risk And Blast Radius

**Blast radius:** Five directories renamed, 20+ cross-reference URLs updated. The changes are confined to the `docs/` tree plus root `README.md` and `tests/`. No agent configuration (`.opencode/agents/`) or template content changes. The `.opencode/templates/product-breakdown/` runtime payload is unaffected.

**Risk:** Stale bookmarks or mental references. If a cross-reference is missed, a link breaks silently. The `tests/test_opencode_workflow_probes.py` file reads paths directly — missed updates there cause test failures.

**Mitigation:** After rename, run a `git grep docs/0` scan to confirm zero stale references remain. The test file validates at runtime.

## Suggested Priority

High — This is a prerequisite for several other candidates (IMP-002 depends on knowing where decisions live; IMP-005 depends on knowing which layer directory is which). Doing it later means updating cross-references twice.

## Task Contract Seed

Rename six docs directories using `git mv`, update all cross-references in `docs/`, `README.md`, and `tests/test_opencode_workflow_probes.py`, then run the existing tests to confirm paths are valid. Remove the explicit layer-mapping section from `docs/README.md` since the directory names now match the template directly.

- Creating missing layer directories (handled by IMP-003, IMP-004).
- Adding new artifact content to layers (handled by IMP-005).
- Changing the `.opencode/templates/product-breakdown/` runtime payload.
