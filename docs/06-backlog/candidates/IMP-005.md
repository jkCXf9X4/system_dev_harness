# IMP-005: Add Missing Per-Layer Artifacts To Existing Layers

## Status

Proposed

## Layer

Evolution

## Theme

Fill in the missing typical artifacts for the four existing layers (intent, product, architecture, implementation) that the template expects but the current docs do not provide.

## Evidence

- `.opencode/templates/product-breakdown/layers/00-intent.md` — Expected artifacts: purpose.md, users.md, outcomes.md, constraints.md, assumptions.md, decisions/.
- Current `docs/01-intent/` — Only has vision.md and use-cases.md. No purpose.md, users.md, outcomes.md, constraints.md, assumptions.md, or decisions/.
- `.opencode/templates/product-breakdown/layers/01-product.md` — Expected artifacts: scope.md, capabilities.md, use-cases/, requirements/, experience/, domain-model.md, glossary.md, decisions/.
- Current `docs/02-product-commitments/` — Only has product-commitments.md. No scope.md, capabilities.md, requirements/, experience/, domain-model.md, glossary.md, or decisions/. Use-cases/ is in the intent layer instead.
- `.opencode/templates/product-breakdown/layers/02-architecture.md` — Expected artifacts: quality-attributes.md, context-view.md, container-view.md, component-view.md, data-view.md, integration-view.md, deployment-view.md, decisions/.
- Current `docs/03-system-architecture/` — Only has architecture.md. No quality-attributes.md, context-view.md, container-view.md, component-view.md, data-view.md, integration-view.md, deployment-view.md.
- `.opencode/templates/product-breakdown/layers/03-implementation.md` — Expected artifacts: code-structure.md, modules/, interfaces/, configuration.md, environments.md, decisions/.
- Current `docs/05-implementation/` — Only has implementation.md. No code-structure.md, modules/, interfaces/, configuration.md, environments.md.

## Current Pain Or Risk

The existing layer directories contain only the artifacts that were most urgent at time of creation. Important structural documents (quality-attributes.md, scope.md, domain-model.md, etc.) are missing. A reader exploring a specific layer cannot find all relevant information in that layer — they must reconstruct it from cross-references. The package does not practice what it preaches about layer completeness.

## Proposed Improvement

For each existing layer, add the key missing artifacts. The content should be extracted from existing documentation (consolidating what is already implicitly present) and should not invent new policy:

- **00-intent/**: Extract purpose from vision.md into explicit purpose.md. Extract users from use-cases.md actors list into users.md. Create outcomes.md extracting the "Desired Outcomes" section from vision.md. Create constraints.md from vision.md "Non-Goals" and architecture.md "Boundaries." Create assumptions.md from implicit assumptions in the architecture and vision docs.

- **01-product/**: Create scope.md explicitly listing what is in and out of scope (extract from vision.md Non-Goals and architecture.md Boundaries). Create capabilities.md summarizing product capabilities from use-cases.md. Move use-cases artifact from intent to product (or add a symlink/redirect). Create domain-model.md documenting the stable concepts from architecture.md. Create glossary.md from terms used across all docs.

- **02-architecture/**: Create quality-attributes.md from the guiding principles and desired outcomes. Create context-view.md documenting external actors and systems. Create component-view.md describing the agent roles and stages. Create integration-view.md describing how agents interact. Create data-view.md describing the artifact flow.

- **03-implementation/**: Create code-structure.md describing the repo layout (from implementation.md). Create modules/ with sub-files for each agent group. Create configuration.md documenting opencode.json settings. Create environments.md listing the environments (local dev, target repo, CI).

## Expected Benefit

Each layer directory becomes a complete reference for its layer. A reader can navigate by layer question ("How is it structurally organized?") and find all relevant documents in one directory. The package becomes a working example of the layered structure it prescribes, strengthening the template's credibility. The content is extracted from existing documentation, so no new policy is created — only consolidation and explicit documentation of implicit knowledge.

## Risk And Blast Radius

**Blast radius:** New files only (10-15 files). No files moved or deleted (except possible move of use-cases.md from intent to product). No agent behavior changes. Content is extracted from existing docs so no new design decisions are introduced.

**Risk:**
- Splitting content across more files could make it harder to find, not easier. The template's load-on-demand philosophy assumes small files; this alignment reinforces that.
- Content duplication: the same concept (e.g., "boundaries") appears in vision.md, architecture.md, and could be extracted into multiple layer files. Cross-reference links should be used instead of duplicating content.

**Mitigation:** Use `> See also: <path>` cross-references rather than copying content. Mark new files as "extracted from <source> — maintained at source" to prevent drift.

## Suggested Priority

Low — Requires IMP-001 (directory renumbering) and IMP-002 (decision distribution) to be complete first, but has no hard runtime dependency. Can be done incrementally over multiple task contracts.

## Task Contract Seed

Pick one layer (e.g., `00-intent/`). Read all current docs in that layer and extract the content needed to create the missing template artifacts. Write those artifacts as new files with cross-references to the source material. Update `docs/README.md` if the file listing changes. Do not touch any other layer.

## Out Of Scope

- Creating verification or operation layer artifacts (handled by IMP-003, IMP-004).
- Moving use-cases.md between layers (this is a separate ownership decision about whether use-cases belong in intent or product).
- Making up content that does not already exist in current documentation.
- Changing any agent prompts or runtime behavior.

## Traceability

- Intent: Vision.md — all desired outcomes and non-goals are source content
- Product: Product-commitments.md — commitments constrain what capabilities exist
- Architecture: Architecture.md — all stable concepts and boundaries are source content
- Implementation: Implementation.md — all stage maps and artifact lists are source content
- Verification: (none direct; verification layer is created in IMP-003)

## Notes

The template's artifact list per layer is labeled "Typical Artifacts" — it is aspirational, not mandatory. The goal of this candidate is not to match the template exhaustively but to close the most visible gaps. Each new file should earn its maintenance cost by answering a clear "layer question" that is not answered elsewhere.
