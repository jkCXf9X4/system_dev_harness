## Evidence

- `agent-boundaries.md` lines 14, 20, 24, 26, 28, 30, 32, 36 — inconsistent verb usage
- `.opencode/agents/orchestrator-verifier.md` line 39 — uses "modify" as the canonical form ("Do not modify files")

## Current Pain Or Risk

Inconsistent verbs ("do not modify", "may edit", "cannot edit", "may write") in agent-boundaries.md create ambiguity about file modification permissions. Different sections use different verbs for the same concept, making it unclear which agents may modify files and under what constraints. The verifier agent already uses "modify" as the canonical term (line 39), but agent-boundaries.md mixes "edit", "modify", and "write" without consistent rules.

## Proposed Improvement

Replace all instances of "edit" with "modify" in agent-boundaries.md. Reserve "write" for file creation (planner writing plan summaries, builder writing new candidate files). Adopt the "modify" convention already established in verifier.md Phase 3.

## Expected Benefit

Single canonical verb for file modification permissions across all workflow files. Reduced ambiguity for agents interpreting their modification boundaries.

## Risk And Blast Radius

Low — single file, wording-only change. No logic or permission boundary changes. No agent behavior is altered.
