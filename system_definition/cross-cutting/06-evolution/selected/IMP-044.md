## Theme

## Evidence

- `stage-output-schema.md` — emit-by-exception rule exists but verbose boilerplate still passes through
- Planner output includes: `helper_not_used` rationales for each waived helper (typically 5-7 entries), `parallel_helper_plan` with packet IDs and dependency details, `helper_dispositions` with `parallel_safe`, `dependencies`, `file_write_set`, `helper_lifecycle` for each helper
- Builder output includes: helper usage rationales, cleanup details, builder-owned review pass results, interface-consistency verification results
- Reviewer output includes: helper dispositions, parallel helper plan, risk triggers detected, blocking gaps, memory candidates
- A typical workflow run with 5 waived helpers produces ~500-1000+ tokens of `helper_not_used` boilerplate per stage

## Current Pain Or Risk

Boilerplate output fields accumulate across stages. A full workflow run with planner, builder, reviewer, reflection, and reporter each producing helper disposition blocks adds 2-5KB of low-value tokens. These fields are primarily process documentation — they verify the workflow ran correctly but provide little substantive evidence for downstream decision-making.

## Proposed Improvement

Add a `compact` output mode to `stage-output-schema.md` where helper disposition blocks are collapsed to a single summary line: `helpers_used: [discovery, contract] | helpers_waived: [architecture, lessons, memory, researcher, systems-engineering]`. Move detailed rationales to an optional `helper_details` block emitted only when `high_assurance` profile is active or when a waiver rationale is non-obvious.

## Expected Benefit

50-70% reduction in boilerplate output tokens for standard and lightweight profiles. Estimated savings of 2-4KB across the full chain per workflow run.

## Risk And Blast Radius

Low — detailed rationales remain available in high_assurance mode. Standard mode already implies lower traceability requirements for helper selection justification. Reviewer gate can request expanded details if needed.

## Task Contract Seed

Add `output_mode` field to `stage-output-schema.md` (`compact` | `full`). Define compact collapse format for helper disposition blocks. Update planner prompt to set `output_mode` based on tailoring profile. Update builder and reviewer prompts for compact-mode output.

## Out Of Scope

Do not remove any evidence requirements. Do not change what helpers produce — only how their usage is reported.
