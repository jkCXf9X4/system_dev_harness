## Theme

Document the rationale for why the new validation stage's `fail` outcome (routing back to planner for revision) is consistent with PD-003's single-gate-authority model ("The reviewer stage is the only completion gate authority").

## Evidence

- PD-003: "The reviewer stage is the only completion gate authority."
- `control-policy.md`: validation `fail` routes back to planner for revision — same routing mechanism as reviewer `blocked`.
- Source: BC-004 from IMP-026 reviewer findings; documented as deferred follow-up in IMP-026 plan summary (Risks section, item #5, line 121).
- Plan file: `.opencode/dev_harness_plans/2026-06-30_160000-IMP-026.md`

## Current Pain Or Risk

Without explicit documentation, future agents or operators may misinterpret validation `fail` as an independent gate decision, or question whether PD-003 needs to be updated. The decision-log gap creates ambiguity about the validation stage's authority relative to the reviewer's gate authority. This is a specific risk because validation `fail` looks similar to reviewer `blocked` (both route back to planner) but they have different meanings: validation is an upstream advisory check, the reviewer is the completion gate.

## Proposed Improvement

Document the PD-003 rationale in the decision log or a dedicated decision record:
- Validation is an upstream advisory check, not an independent completion gate.
- Validation `fail` routes to planner revision using the same mechanism as reviewer `blocked`, but the trigger and meaning are different: validation identifies intent-alignment gaps early; reviewer performs final gate verification.
- PD-003's single-gate-authority model is preserved because only the reviewer can block completion permanently (validation `fail` sends back for revision; reviewer `blocked` halts the task).
- Either create a new decision record file or add a rationale section to an existing decision-log artifact.

## Expected Benefit

- Eliminates ambiguity about validation stage authority.
- Prevents future misinterpretation of validation `fail` as a completion gate decision.
- Provides a clear decision-log reference for PD-003 consistency review.
- Future agents can reference the documented rationale instead of rediscovering it.

## Risk And Blast Radius

Low — decision-log documentation only. Single file creation or update. No code, agent, or workflow policy changes. No behavioral impact.
