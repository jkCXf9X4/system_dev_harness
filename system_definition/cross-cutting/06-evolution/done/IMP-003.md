## Current Pain Or Risk

Durable workflow memory is intended for repeatable lessons, patterns, and decision pointers. The project did not previously define a separate searchable task-history path for prior task evidence, review outcomes, rejected candidates, or run-level observations. That created pressure to over-promote historical detail into always-retrieved memory.

## Proposed Improvement

Define an explicit boundary between:

- durable workflow memory under `.opencode/dev_harness_memories/`
- task-local implementation and review evidence
- searchable or traceable historical task summaries, if the project chooses to add them later
- improvement candidates under `system_definition/cross-cutting/06-evolution/candidates/`

Add guidance to memory and reporter prompts so useful history can be referenced without becoming default memory.

## Expected Benefit

Keeps always-retrieved memory small and high signal while preserving a future path for looking up prior task evidence when needed.

## Risk And Blast Radius

Medium. This may require a small architecture decision if a new historical evidence location is introduced. If limited to boundary documentation, the blast radius is low.
