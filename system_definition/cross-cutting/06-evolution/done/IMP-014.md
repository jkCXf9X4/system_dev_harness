## Theme

PBS / Visualization — Add visual Product Tree per INCOSE Figures 1.7 and 2.24

## Evidence

- `system_definition/README.md` — Current PBS is documented in tables and prose only. No visual tree diagram exists.
- `system_definition/cross-cutting/06-evolution/README.md` — The evolution layer references improvement candidates in table format without a structural overview.
- `SE_V5/INCOSE_SEHB5.txt` line 1537 (§1.3.5) — References Figure 1.7, which uses a tree diagram to show hierarchy within a system: "hierarchy within a system is an organizational representation of system structure using a partitioning relation."
- `SE_V5/INCOSE_SEHB5.txt` lines 4770–4773 (§2.3.4.1) — States "The Product Tree, also called System Definition Structure (PBS), is a breakdown of the SoI into successively lower-level details of its physical architecture" and references Figure 2.24, "The breakdown structures."
- `SE_V5/INCOSE_SEHB5.txt` lines 5111–5123 (§2.3.4.7) — Notes the product structure "should be a useful decomposition of the elements of the SoI that explores the trade space" for trade studies.

## Current Pain Or Risk

- Current PBS uses only tables and text, making parent-child relationships and hierarchy levels difficult to scan.
- New contributors must read through multiple documents to understand the decomposition structure.
- Inconsistencies between the layer numbering (00–06) and the logical parent-child relationships are not visually apparent.
- Without a diagram, span-of-control analysis (7+/-2 heuristic per Urwick, 1956) cannot be easily performed.

## Proposed Improvement

Add `system_definition/product-tree.md` containing a visual Product Tree diagram using Mermaid (or ASCII as fallback). The diagram should show:
- SoI root (`system_dev_harness`)
- Primary subordinate elements (Intent, Product, Architecture, Implementation, Verification, Operation, Evolution)
- Further decomposition down to atomic leaves where applicable
- Annotations for element type (atomic vs. decomposable)
- Cross-references to the corresponding PBS directories

## Expected Benefit

- Visual representation makes parent-child relationships immediately scannable.
- Span-of-control violations (more than 7+/-2 subordinates at any level) become visually apparent.
- New contributors can grasp the PBS structure in seconds.
- The diagram serves as a navigation aid for the directory structure.
- Supports INCOSE Figure 1.7 and 2.24 conventions for documenting breakdown structures.

## Risk And Blast Radius

**Low** — documentation-only artifact. No existing files are moved or restructured. Risks:
- Must stay synchronized with structural PBS changes (outdated diagram is worse than no diagram).
- Mermaid rendering depends on viewer/editor support; ASCII fallback needed for universal compatibility.
- The diagram references directory paths that could go stale if the tree structure is reorganized.
