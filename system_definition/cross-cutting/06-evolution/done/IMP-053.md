## Current Pain Or Risk

Plan files are inconsistent (14-242 lines). Builder/reviewer/reflection/reporter instructions say they load fields from the plan file that the schema doesn't require. When a planner writes a minimal plan file, downstream agents get a header, not "full context." The pfv-002 check can't detect missing `success_criteria` because it's not in the schema.

## Proposed Improvement

Expand `plan-summary-schema.md` from 8 to 14 required fields (adding `schema_version`, `success_criteria`, `workflow_mode`, `issue_kind`, `control_flags`) plus 9 conditionally-required fields with trigger conditions. Add `schema_version: v2` for version-aware pfv-002 checking in the reviewer. Update 5 downstream agent files to enumerate the expanded field set in their Plan File Loading sections.

## Expected Benefit

Every plan file consistently contains all context downstream agents need. Builder can actually "reconstruct full context." Reviewer can detect missing fields before approval. Reflection and reporter have structured success criteria. New schema_version enables future expansions without breaking existing plan files.

## Risk And Blast Radius

`cross-module` — 6 files (1 schema + 5 agent instruction files). Additive only — no fields removed or renamed. No code behavior changes. Primary risk: pfv-002 could false-fail on existing plan files; mitigated by `schema_version`-aware checking.
