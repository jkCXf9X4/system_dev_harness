## Current Pain Or Risk

The workflow supported risk-based adaptation and `not_applicable` stage declarations, but it did not record why a particular process configuration was chosen for a given task. That made the tailoring choice difficult to audit, compare across similar tasks, or reuse as a governance signal.

## Proposed Improvement

Add a lightweight tailoring documentation mechanism:

1. Planner work orders include a structured `tailoring_record` section with the selected workflow profile, applied triggers, helpers or stages intentionally waived or intensified, and the rationale for that process configuration.
2. The standardized plan summary persists the same record alongside the task archive file in `.opencode/dev_harness_plans/`.
3. The reporter includes a tailoring summary in the final control report so the adapted process remains visible after completion.

## Expected Benefit

- Every process tailoring decision is documented with rationale.
- Future planners can reference past tailoring records for consistency.
- The workflow gains an auditable process-adaptation trail without adding a separate approval path.

## Risk And Blast Radius

- Adds a required section to the planner work order and plan summary schema.
- Constrains planner and reporter prompts to preserve tailoring information.
- Low blast radius: confined to workflow policy, prompt text, and verification artifacts.
