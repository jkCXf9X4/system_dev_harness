## Theme

Policy file modularization

## Evidence

- `control-policy.md` (184 lines) covers 8 distinct topics: Required Stages, Route Selection, Tailoring, Stage Output Schema, Plan Draft Approval, Initial Clarification Gate, Candidate Capture Disposition, Workflow Memory, Final Reflection, Adaptive Risk Triggers, Parallel Helper Execution, Control Flags, Handoff Boundary, Waivers, Revision Loop Policy
- `planner-triggers.md` (66 lines) covers planner, builder, and reviewer triggers in one file
- Agents load entire files when they need only specific sections: planner needs ~60 lines of `control-policy.md`, reviewer needs ~40 lines, contract needs ~10 lines
- Planner prompt references `control-policy.md` and `planner-triggers.md` explicitly
- Reviewer prompt references `control-policy.md` explicitly
- Contract prompt references `control-policy.md` explicitly

## Current Pain Or Risk

Every agent that references `control-policy.md` loads all 184 lines. For reviewer, 144 of 184 lines (78%) are irrelevant. For contract, 174 of 184 lines (95%) are irrelevant. This wastes tokens on every agent invocation that references these files. The wasted tokens scale linearly with the number of agents and workflow runs.

## Proposed Improvement

Split `control-policy.md` into topic-focused files: `route-selection.md`, `clarification-gate.md`, `plan-draft-approval.md`, `waivers.md`, `revision-loop.md`, `control-flags.md`, `handoff-boundary.md`, `tailoring.md`. Keep a master `control-policy.md` as an index/overview. Split `planner-triggers.md` into `planner-triggers.md`, `builder-triggers.md`, `reviewer-triggers.md`. Update agent prompts to reference only the files they need.

## Expected Benefit

Per-agent policy load reduced by 50-80% for `control-policy.md` references. Reviewer loads ~40 lines instead of 184. Contract loads ~10 lines instead of 184.

## Risk And Blast Radius

Medium — file splitting creates more files to maintain and could cause reference breakage. Some topics are cross-referenced within the file (e.g., Tailoring references Adaptive Risk Triggers and vice versa). Mitigation: keep a master index file, update all cross-references systematically, run grep for stale references.
