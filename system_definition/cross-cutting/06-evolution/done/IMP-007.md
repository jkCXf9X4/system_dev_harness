## Current Pain Or Risk

Memory incorporation is currently opportunistic. Reviewer, reporter, and focused improvement evaluator may invoke `orchestrator-memory-curator` when they notice evidenced repeatable findings, but no end-of-work stage owns the question "what should be remembered from this run?" As a result, durable lessons and reusable patterns can be missed when the task completes successfully, especially if the reviewer focuses on approval and the reporter only summarizes prior stage outputs.

## Proposed Improvement

Add a dedicated final reflection task near the end of guarded delivery and improvement workflows. The reflection task should review the completed run and decide whether there are durable memory candidates, rejected memory candidates, or no memory action.

The reflection task should inspect:

- planner assumptions and clarification decisions
- builder implementation evidence
- verifier and reviewer findings
- waivers or blocked iterations
- repeated mistakes or successful reusable patterns
- improvement candidates raised during the run
- memory entries used or contradicted during the run

It should return:

- reflection_status: `memory_written`, `memory_rejected`, `needs_more_evidence`, or `no_memory_action`
- memory candidates evaluated
- durable lesson or pattern IDs written or updated
- rejection rationale for candidates not written
- evidence source for each memory decision
- follow-up improvement candidates, if reflection exposes a workflow problem

The reflection task may be implemented as:

- a new `orchestrator-reflection` agent that owns final memory triage, or
- an explicit required reporter subtask that invokes `orchestrator-memory-curator` when candidates are present.

Selected implementation: new `orchestrator-reflection` agent.

## Expected Benefit

Creates clear ownership for memory incorporation and reduces missed lessons after successful or partially successful tasks. It also separates final reporting from durable memory triage, making memory writes more deliberate and auditable.

## Risk And Blast Radius

Medium. A new required stage or reporter-owned subtask adds workflow overhead and could create noisy memory candidates if the criteria are weak. The reflection task must reject one-off observations, implementation evidence, temporary task state, and backlog items that do not belong in memory.

## Task Contract Seed

Implemented by adding a new `orchestrator-reflection` agent, routing completed delivery and improvement outputs through reflection before reporting, and updating reporter and workflow policy so reflection owns final memory-incorporation triage. Memory writes remain limited to `.opencode/dev_harness_memories/lessons.md` and `.opencode/dev_harness_memories/patterns.md` through `orchestrator-memory-curator`.

## Out Of Scope

- Making every task write memory.
- Storing task transcripts as durable memory.
- Replacing `orchestrator-memory-curator`.
- Combining memory reflection with improvement backlog persistence.
