## Theme

Shared context optimization

## Evidence

- `opencode.json` — current config has `"instructions": [".opencode/dev_harness/instructions.md"]` but no `contextPaths` entry
- OpenCode supports `contextPaths` in `opencode.json` that pre-loads files into the system prompt once per session under "# Project-Specific Context"
- Files loaded by every agent: `_common-policies.md` (727B), `stage-output-schema.md` (3KB)
- Every agent prompt includes "Common policies: `.opencode/dev_harness/workflow/_common-policies.md`"
- `sync.Once` in OpenCode source ensures contextPaths files are loaded once per session
- OpenCode source (`internal/config/config.go`): `defaultContextPaths` includes common instruction files but dev_harness files would need explicit configuration

## Current Pain Or Risk

Every agent invocation independently loads `_common-policies.md` and `stage-output-schema.md`. With 5+ agents per workflow run, the same ~4KB is loaded 5+ times. OpenCode's `contextPaths` feature exists to eliminate exactly this pattern — files are loaded once per session and injected into the system prompt. The current configuration doesn't use it, so every agent pays the cost of re-reading and re-processing these shared files.

## Proposed Improvement

Add `_common-policies.md` and `stage-output-schema.md` to `contextPaths` in `opencode.json`. Remove explicit "Common policies: ..." references from agent prompts for these files. Verify that contextPaths-loaded content is available to subagents (the `task` agent type in OpenCode).

## Expected Benefit

Eliminates redundant loading of ~4KB per agent invocation. For a 5-agent workflow, saves ~16KB of duplicate context. Also reduces agent prompt verbosity by removing explicit load instructions.

## Risk And Blast Radius

Medium — contextPaths behavior for subagents may differ from primary agents. OpenCode's `CoderPrompt()` and `TaskPrompt()` functions inject contextPaths content into the system prompt for those agent types, but subagent behavior needs verification. If subagents don't receive contextPaths content, agents that lost their explicit references would miss the policy content. Mitigation: test with a single agent first, verify subagents receive the pre-loaded context. Fall back to explicit references if subagents don't receive contextPaths content.

## Notes

OpenCode source code shows `contextPaths` files are loaded via `sync.Once` in the config and injected into `CoderPrompt()` and `TaskPrompt()` as "# Project-Specific Context". Subagents running as separate sessions may not inherit this. If subagents don't receive contextPaths content, the fallback is to keep explicit references in agent prompts but use contextPaths for the primary orchestrator agent.
