- Observed gap: planner summaries are ephemeral — no systematic archive exists for post-hoc review, pattern discovery, or regression analysis

## Current Pain Or Risk

The planner produces a structured summary for each task, and the builder uses it as the implementation contract. However, no mechanism persists these summaries beyond the current execution session. This means:

- Pattern discovery across tasks requires manual recollection or ad-hoc notes.
- Regression analysis (e.g., "when did we last refactor this module?") has no queryable record.
- Information-hygiene rules cannot verify plan consistency or evolution over time.
- The improvement backlog has no durable cross-reference to the plans that produced candidate findings.

## Proposed Improvement

Add a builder-stage or planner-stage obligation to write a standardized plan summary to `.opencode/dev_harness_plans/<timestamp>-<task-id>.md`. The directory `.opencode/dev_harness_plans/` would be created as part of implementation.

Each summary would include:
- task ID and timestamp
- plan scope and objectives
- files or modules touched
- risk or blast-radius assessment (from the planner summary)
- linked improvement candidate IDs (if any)

The information-hygiene rules would be updated to recognize this directory as a searchable historical record.

## Expected Benefit

Creates a durable, searchable task-history trail that supports pattern discovery, regression analysis, and cross-task traceability without polluting always-retrieved workflow memory.

## Risk And Blast Radius

Medium. Affects planner output format, file-system layout (new directory), and information-hygiene rules. The new directory must be gitignored or treated as volatile to avoid diff pollution. Existing workflow stages are additive-compatible (no behavioral change if the directory is missing).

## Task Contract Seed

1. Create `.opencode/dev_harness_plans/` directory with a `.gitkeep` and a `README.md` describing the archive purpose and naming convention.
2. Update the planner stage to emit a standardized summary header that includes task ID, scope, touched files, risk assessment, and candidate linkages.
3. Update the planner stage to write the summary to `.opencode/dev_harness_plans/<timestamp>-<task-id>.md` before execution begins.
4. Update information-hygiene rules to include the plans directory as recognized volatile content.
5. (Optional) Add a cleanup or retention policy to prevent unbounded growth.

## Out Of Scope

- Persisting full conversation transcripts or raw model outputs.
- Building a search index or vector store over the plans.
- Requiring plan persistence for non-implementation tasks (research, review-only).
- Modifying memory entry format or memory retrieval behavior.
