## Current Pain Or Risk

The guarded chain currently moves from planner summary directly to builder execution without any pre-flight gate. When a task touches many files, performs destructive operations (reorganization, renames, bulk edits), or has a high cost/time estimate, there is no standard mechanism to require a human or summary review before execution proceeds. Without an operational definition of "larger job," every task is treated identically regardless of blast radius.

## Proposed Improvement

Define a `large-job-guidelines.md` artifact with explicit criteria for what constitutes a larger job:

- file count threshold (e.g., >10 files changed)
- blast radius indicators (cross-module, destructive, renaming, deletion)
- destructive operation flag (renames, deletions, schema changes)
- cost or time threshold (e.g., estimated >15-minute execution)

Add a planner-owned pre-approval classification step: when the planner work order matches any large-job criterion, the planner sets `large_job_triggered: true`, records the matching criteria, and requests explicit operator approval before the orchestrator forwards the work to the builder.

## Expected Benefit

Reduces the risk of unapproved large-scale changes, gives the operator a natural checkpoint to review scope before committing, and makes blast-radius decisions explicit and auditable.

## Risk And Blast Radius

Medium. Modifies planner output, orchestrator routing behavior, and adds a new guidelines artifact. Existing small tasks are unaffected (no new gate for them). The pre-approval flow must be lightweight to avoid friction for genuinely urgent or simple bulk changes.

## Task Contract Seed

Create `large-job-guidelines.md` under `.opencode/dev_harness/workflow/` or `product-breakdown/` defining:
- file-count threshold
- blast-radius categories (local, cross-module, destructive)
- destructive-operation flag list
- estimated-cost or time threshold

Add a pre-approval checkpoint in the planner stage of the guarded chain. The planner reads the work order scope, evaluates it against the large-job criteria, records `large_job_triggered`, and requests explicit operator confirmation when criteria are met. The orchestrator pauses on the planner's `user_feedback_required` output and forwards approved work to the builder.

## Out Of Scope

- Blocking non-destructive bulk changes that are fully reversible (e.g., automated formatting).
- Adding a multi-stage approval chain or role-based authorization.
- Changing the reviewer or verifier stages.
