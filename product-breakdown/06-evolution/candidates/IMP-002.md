## Current Pain Or Risk

The memory curator has useful rejection rules, but rejected candidates do not have a standardized reason taxonomy. Without explicit save/skip reasons, memory review can be inconsistent and later agents cannot easily learn whether a candidate was rejected as duplicate, one-off, vague, rediscoverable, unsafe, too broad, or better suited to the improvement backlog.

## Proposed Improvement

Add a compact memory curation decision taxonomy:

- accepted: durable lesson
- accepted: reusable pattern
- accepted: decision pointer
- rejected: duplicate
- rejected: one-off or task-local
- rejected: vague or not actionable
- rejected: rediscoverable
- rejected: unsafe or untrusted content
- rejected: belongs in improvement backlog
- needs_more_evidence

Require `orchestrator-memory-curator` to return one reason and short evidence for every rejected or deferred candidate.

## Expected Benefit

Improves consistency of memory curation, makes rejected memory candidates auditable, and reduces pollution of durable memory with temporary task state.

## Risk And Blast Radius

Low to medium. Primarily affects prompt output shape and memory curation review. Existing behavior should remain compatible if the new field is additive.
